# Phono-PinyinSegment

Phono-PinyinSegment 是与 PhonoP2C 配套的轻量拼音间隙评分模型。它接收连写、无声调的拼音字母，并为每一对相邻字符之间输出一个边界 logit。生产环境不会逐点阈值切分，而是让 phono-core 在合法拼音词表构成的 Trie DAG 上寻找总分最高的路径。例如，`nihaoma` 包含七个字符和六个输出位置，目标边界对应 `ni hao ma`。

Phono-PinyinSegment is the lightweight pinyin gap scorer paired with PhonoP2C. It consumes concatenated, tone-free pinyin letters and emits one boundary logit for every adjacent character pair. Production decoding does not threshold gaps independently; phono-core searches for the highest-scoring path in the Trie DAG induced by the legal pinyin vocabulary. For example, `nihaoma` has seven characters and six output positions, and the target boundaries recover `ni hao ma`.

## 架构

Hugging Face `PinyinSegmentModel` 由 embedding、pre-norm 残差 depthwise-separable convolution blocks 和二分类头组成。Depthwise convolution 使用 channels-last 内存格式，pointwise 路径为 Linear Up-SiLU-Gate-Down SwiGLU；末端的 valid width-2 depthwise contraction 将长度 `L` 映射为 `L-1` 个间隙特征。模型规模很小，当前训练保持单机单卡设计。

## Architecture

The Hugging Face `PinyinSegmentModel` consists of an embedding, pre-norm residual depthwise-separable convolution blocks, and a binary classification head. Depthwise convolutions use channels-last memory format, while the pointwise path is a Linear Up-SiLU-Gate-Down SwiGLU. A final valid width-2 depthwise contraction maps length `L` to `L-1` gap features. The model is deliberately small, so training currently remains single-process and single-GPU.

## 数据与训练

本项目不重复实现预处理流水线。训练读取 PhonoP2C 已生成的 MDS 数据集，验证读取 `val_original`；其中扁平的 `pinyin_list` 已经是消歧后的读音序列。在线增强仅使用 `drop_vowels`、`drop_last_vowel` 和 `vowels_droprate`。Checkpoint 只保存 Hugging Face 模型配置、权重与解析后的训练配置，不保存 optimizer 或 scheduler 状态。验证报告 loss、逐间隙准确率 `ACC` 和整序列准确率 `S-ACC`。

## Data and Training

This project does not duplicate the preprocessing pipeline. Training reads the MDS dataset generated by PhonoP2C, while validation reads `val_original`; its flat `pinyin_list` field already contains disambiguated pronunciations. Online augmentation is limited to `drop_vowels`, `drop_last_vowel`, and `vowels_droprate`. Checkpoints contain only Hugging Face model configuration, weights, and the resolved training configuration, without optimizer or scheduler state. Validation reports loss, per-gap accuracy (`ACC`), and exact sequence accuracy (`S-ACC`).

## 使用方法

```bash
pixi run test
pixi run train
pixi run demo -- nihaoma --checkpoint <checkpoint-dir> \
  --pinyin-vocab <pinyin-vocab.txt>
pixi run python main.py task=export
```

Hydra 参数可以直接覆盖，例如 `pixi run train system.optim_8bit=false model=tiny`。使用 `task.loss_type=focal` 可将默认 BCE 换成 focal loss；`task.focal_loss_alpha` 和 `task.focal_loss_gamma` 分别控制类别权重与 focusing strength。导出的输入、输出、动态长度、模型元数据与量化选项位于 `config/task/export.yaml`。移动端图的 batch 固定为一，输入长度动态范围为 3 到 512；更短输入由 phono-core 直接交给 checked FMM，不会调用或填充评分模型。

## Usage

Hydra values can be overridden directly, for example with `pixi run train system.optim_8bit=false model=tiny`. Set `task.loss_type=focal` to replace the default BCE with focal loss; `task.focal_loss_alpha` and `task.focal_loss_gamma` control class weighting and focusing strength. Export inputs, outputs, dynamic lengths, model metadata, and quantization options live in `config/task/export.yaml`. The mobile graph has a static batch size of one and a dynamic input length from 3 through 512; phono-core routes shorter inputs directly to checked FMM without invoking or padding the scorer.
